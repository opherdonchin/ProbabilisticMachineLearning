## HMM evidence: an honest simulated encounter

The [NumPy probe](notebook_feasibility/sequence_probe.py) implements normalized forward and consistently scaled backward recurrences, evidence as a sum of log normalizers, and smoothed marginal probabilities. With `A_ij=P(z_t=j|z_(t−1)=i)` and likelihood `λ_t(j)`,

$$f_t(j)=\frac{\lambda_t(j)\sum_i f_{t-1}(i)A_{ij}}{c_t},\qquad b_t(i)=\frac{\sum_j A_{ij}\lambda_{t+1}(j)b_{t+1}(j)}{c_{t+1}},\qquad \gamma_t(j)\propto f_t(j)b_t(j).$$

Filtering conditions on observations through t; smoothing uses the complete sequence. A backward likelihood is not itself a normalized state distribution. The state separator explains why messages summarize all relevant past/future histories; graph sparsity by itself does not guarantee exact tractable integration.

[Results](notebook_feasibility/sequence_results.json) check every filter marginal by independent prefix enumeration and every smoothed marginal/evidence by complete enumeration, for the existing symmetric three-step example and a new five-step asymmetric transition/emission model. Maximum discrepancies are `2.3e−16`. The existing oracle evidence `.1178`, unique path MAP `000` and marginal modes `001` remain intact. The asymmetric case catches transposed transition indexing. Final filtering=smoothing, unchanged prefix filters under appended observations, normalized marginals and explicit all-zero-likelihood failure pass. This validates the numerical algorithm, not a student-written notebook.

The 200-roll simulated fair/loaded model uses the exact currently supplied probabilities, seed84 and known truth. It is **not empirical behavior, labeled-context sensor data or Murphy's precise random realization**. Average true-state negative log scores are `.51175` filtering, `.41351` smoothing, `.61072` independent-emission baseline using stationary state prior `(2/3,1/3)`. State accuracy and posterior probabilities are separately recorded. Smoothing need not improve every realized state decision or reduce entropy for every observation; this one synthetic result is a mechanism illustration, not a scientific validation of state meaning.

Dense recurrence work is `O(TK²)` rather than `K^T` path enumeration. At K=2, T=200/2,000/20,000, measured message time is approximately `.00093/.00914/.08985` seconds (imports excluded), showing linear time scaling. K=8/16 remain Python-loop dominated at these sizes, so the wall times do not empirically establish quadratic K scaling; the explicit dense arithmetic count does. Stored filter/backward/smoothed arrays cost `O(TK)`, while streaming filtering needs `O(K)` work memory. Exact posterior probabilities under supplied parameters do not remove model error or uncertainty about those parameters.
